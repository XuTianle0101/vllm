# 08: 完成整理后验收与性能比较

**What to build:** 提供足以判断整理是否引入回退的当前代码验收记录，使维护者能够在保留已知精度问题的前提下确认功能、正确性和代表性性能变化。

**Blocked by:** 07 — 清理历史实验资产并收敛文档。

**Status:** ready-for-agent

- [ ] 按实际修改范围运行仓库要求的相关测试、静态检查及模型评估，记录准确命令、代码版本、环境与结果。
- [ ] HF 对照使用原输入和原容差，覆盖 summary/窗口边界、分块 prefill、多步 decode 及全部保留的已知失败复现；不得通过放宽容差或删除失败用例使验收显示通过。
- [ ] 标准执行路径验证 eager/graph、批处理、取消、缓存复用及标准服务行为；普通 Qwen3 功能回归保持有效。
- [ ] 以 01 固定的环境、短/中/长上下文用例、测量口径和性能标准完成整理前后比较；存在环境差异时明确说明可比性限制，不以历史报告替代整理前基线。
- [ ] 验收记录明确区分既有失败、新增回退和未执行项目；环境阻碍要记录原因，不计为通过，缺少必要证据时不声称验收完成。
- [ ] 所有新增回退在完成本票前解决并重新验证；历史精度问题继续作为已知问题，不将其根因诊断与修复扩入本次范围。
- [ ] 确认生产路径和保留验证不依赖已删接口及资产，记录最终代码状态，供后续历史重写核对。
