## 精度与内存契约

A100-SXM4-80GB、BF16、TP=PP=1；冻结基线 `T00-305bf8f9dc429f1af60e`，
容差 `T00-tol-fbd0eb931ac1c7153403`，未修改 HF 环境、权重或门禁。

- 完整回归 116/116 通过，含真实 CUDA Graph 捕获和 32 组直接分页 kernel/oracle
  比较：FP32/BF16、四种窗口、共享/独立页池、decode/mixed chunk、随机物理槽位、
  短尾、summary 自身、空 split、重排和槽位复用。FP32 `atol=rtol=2e-6`，
  BF16 `atol=rtol=0.008`。
- 17 个冻结教师强制案例 × Triton eager/graph × T05 eager/HF：68/68 通过。
  对 T05 最大 logits 误差 2.5、RMSE 0.738129；对 HF 分别为 2.75、0.656518。
  两种参考的最大 top-1 分歧 margin 都为 0.25，低于冻结门禁 0.5。
  这不是生成轨迹或 logits 逐位相同的声明。
- 生产 attention 直接读取物理页，不构造平方 mask、不 gather 完整历史、不重复 GQA KV，
  不逐请求调用 Python attention。Python 遍历仍用于 metadata 和延迟 KV 提交。
  prefill tile 在线 softmax；decode 8 路 split-K 以最大值/指数和稳定合并，
  没有将两个独立归一化的 attention 输出直接相加。
- CPU 和显式参考路径保留原实现；无分页 cache 只用于参考验证。

## 测量范围

1K/4K × batch 1/4/8，32 decode 步，一次预热与五次正式重复。
对照在同一 A100、同一进程顺序运行，使用相同 checkpoint、输入和执行配置。
T05 对照通过 `model.triton_attention=False` 使用原数学计算和历史 staging。
标准 CUDA Graph 仍需显式开启，未修改服务默认配置。

decode 墙钟区间包括 metadata、KV、全部 36 层、LM head 与 greedy；
prefill 另测 packed batch、KV 提交与末行 logits/greedy。
不包含 scheduler/网络，不作为 HTTP 吞吐或 128K 性能验收。
首次 JIT/capture 单列，正式重复不得发生新捕获。

## 标准 V1 与最终修复

最终代码及 V1 运行：`14a46ddc3af405ceac6647305d736cf59a22d229`。
[V1 指标与原始文件哈希](v1-summary.json)，原始目录 `../results/T06/v1-14a46ddc3a/`。

首轮 V1 初始化暴露 profiling 假页池缺少物理槽位的问题。修复提交
`e6596429fc840a9b0ca8c0cc5b739facc5354cc8` 以一页零 KV 配合完整线性 metadata
模拟历史，避免将 scheduler KV 计入激活；新增两项 CUDA 启动回归。
初次失败日志保留在 `../results/T06/v1-a368e0356e/run.log`。
最终提交进一步以共享窗口的前缀计数和 index_select 替代 metadata 布尔索引同步；
不改 Triton 内核数学计算。此后重跑受影响专项（含 GPU） 38/38 通过。

真实 V1 对 T05 SDPA 同前缀比较 8/8 通过；精度阶段 62 次 replay、5 次捕获。
7/1023/1024-token 请求两轮各生成 32 token，轨迹完全相同；8-token 请求两轮
均在第三个输出处分歧，首次分歧 margin 0.25。只比较共同前缀，不混比后续轨迹。
独立页池、257-token 调度预算、chunked prefill 和请求逆序均覆盖。

另移除逐请求 logits 导出钩子，测量真实 scheduler + prefill + 32-token decode
总耗时：四个请求长度为 1024/1023/1022/1021，预热一次、正式五次；不含 HTTP。
