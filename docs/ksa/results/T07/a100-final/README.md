## 验收发现与修复

1. 移除遗留的 8192 文本上限，使用 131072；单次 chunk 仍限 4096。
   standalone 页池按配置的最大上下文分配，短请求不会因全局上限扩大而默认分配 128K 页池。
2. V1 KV 提交原先按 36 层重复构造相同页组槽位，并在 GPU 上做动态布尔索引和页号检查。
   改为每次提交按共享页组复用映射、每种窗口复用保留位置；页号在 CPU 检查，
   新 KV 通过固定整数索引写入，空 summary 不执行无效写入。attention 数学计算未改。
3. 单请求 4K graph、128 输出、预热后五次的修复前诊断为
   49.61–50.04 ms/token，修复后为 15.02–15.10 ms/token；两次测量均包含 V1 调度。
   原始数据在 `smoke-graph-2/` 与 `smoke-graph-3/`。
   前者代表 T06 已交付的 V1 提交逻辑，非 T06 单模型计时；不能将两种计时范围混用。

4. BF16 prefill 的 query tile 从 32 扩大到 128，保留 64-key softmax 分块；
   32K TTFT 从 11.39–11.40 s 降至 6.608–6.615 s。128×128 双 stage 尝试因
   A100 共享内存不足而弃用，日志保留；生产采用 128×64、双 stage。
   混合批次跳过全部 query 都越界的 tile，避免短 decode 扫描无效的大段历史。
5. V1 图缓存最多保留 8 个形状，覆盖 8 请求逐个结束的 batch 大小；配置并发小于 4 时仍保留 4 个。
   调整前每次正式重复重捕获 8 次；调整后五次均为零。诊断计数通过快照保留，
   不再共享可变列表；对应 CPU 契约测试通过。

- 首轮全长度冻结教师位置比较 23/23 通过，包含 130944 输入和三组长距离检索输入；
  这轮运行在 KV 提交优化之前，最终版本复测需另记。
- 最终扩展 KSA 测试 132/132 通过，包括真实 GPU、分页/短尾/summary 自身、
  非连续页、图重排与页复用；上限边界增加到 131072。
- 普通 Qwen3：确定性小权重、原生 `Qwen3ForCausalLM` / `GPUModelRunner`，两例 16-token
  生成的同前缀全词表 logprobs 对 HF 通过。最大误差 0.007792 / 0.004803，
  第一例 token 完全一致，第二例首处分歧是 margin 0.001953 的 BF16 近似并列。
  单独门限是 logprob 0.05 / margin 0.02；不是 KSA T00 容差修改。
  这是原生路径数值回归，不是预训练 Qwen3 能力评测。

- 全长度真实缓存 decode：23 用例 × eager/graph，共 46/46 通过；
  最大 logits 误差 7.375、RMSE 2.16734、logprobs 误差 4.90624、top-1 分歧 margin 0.25。
  实现提交 `96b3994f7431a827219caf299e999c98ea969967`；后续只增加无效 tile 跳过与 V1 图缓存容量，
  最终 V1 验证另测。674219/674219 页归还，192 次 graph replay。
