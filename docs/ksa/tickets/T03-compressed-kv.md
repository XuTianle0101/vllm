# T03：压缩 KV 与 Python 优化

- 状态：DONE（分页缓存及四组 A100 实验通过）
- 依赖：T02 DONE
- 目标：在精度不变的前提下实现真实 KV 压缩并减少 Python 路径开销。

## 实现范围

将短窗口文本页与 summary 页纳入 vLLM 缓存规格、容量估算和生命周期，长窗口层保留文本页。保留局部 summary，直到其成为远端可见，避免过早丢弃；请求释放必须回收所有组。

删除无效计算和冗余复制，降低同步开销。优化逐项提交或保留明确开关用于比较，记录每项改动相对 T02 的收益。暂不编写 Triton。

## 服务器实验

比较 HF、T02 和当前版本的精度；覆盖淘汰前后、部分块、重复复用和非连续物理页。测量 KV 页占用随长度增长、峰值显存和 TPOT，区分有效 KV 与预分配总池。

## 门禁与反馈

精度无回退；短窗口层增长符合 O(1024 + N/8)，无越界或泄漏。每项优化给出独立测量；收益不超过波动时如实记录，不宣称提升。长上下文尚不能运行的原因进入后续工作记录。

## 本轮实现

- 单请求 runner 默认使用 `KVCacheManager`、`KVCacheConfig` 与真实共享物理页池。
  每层文本页与 summary 页分别建组；短窗口文本页淘汰，长窗口保留文本，所有已完成
  summary 保留至请求释放。基础服务与批处理仍属于 T04。
- 页容量包含空页、部分页和提交余量；结束、异常及显式取消 `cache.clear()` 释放所有组。
- 保留张量对照路径、逐层/批量页提交开关与预填充临时张量保留开关，以独立测量收益。
- 新增真实非连续页、重复复用、请求隔离、页池耗尽、写入失败及 8K 页容量测试。
